COLOR ATLAS · GUIDE

Explore how color models organize color

A color atlas arranges colors by attributes such as hue, lightness and chroma. This app shows a grid of calculated colors: one attribute stays fixed while the two axes vary. It is a tool for learning, teaching and investigating color-model behavior.

By Fernando Voltolini de Azambuja. Color Atlas began as a graduate coursework project in 2024 with my classmates Nima Rabbanifar and Soroush Shahbaznejad. For version 2, I fixed a few issues and made improvements to the app.

Try a constant-hue slice

Select CAM16, choose Fixed h | C x J, and set the fixed hue to 180. Chroma C increases from left to right; lightness J increases upward. Move the hue slider to browse another slice, or enter an exact value. Click a tile to inspect its coordinates, XYZ and selected-space RGB. Gaps between tiles have no sample.

A color-appearance model predicts attributes from XYZ values and viewing conditions. The atlas runs it in reverse: each tile requests an attribute combination and calculates the required XYZ values. Change one viewing condition to explore how those values change. For brightness Q planes, the sampled range also follows the adopted white.

What the preview means

The selected RGB space defines the gamut test and numerical RGB values. Every visible patch and scientific background is encoded as sRGB. Linear sRGB therefore changes numerical RGB, not the preview transfer function. The screen is not characterized or calibrated by this app.

  • Displayable: inside both the selected gamut and sRGB.
  • Orange outline: inside the selected gamut but outside sRGB; the displayed sRGB values are clipped.
  • Dot: outside the selected gamut; no color patch is drawn.
  • Cross: no valid model result for that sampled tuple.

The inclusive RGB cube uses a tolerance of 10−6 in encoded channel values. Classification uses unclipped values; only boundary noise and explicitly identified previews are clipped.

MATLAB's xyz2rgb Bradford conversion from the adopted white to each RGB space's native white is a numerical preview convention. It is separate from the appearance model's adaptation degree D. This is not an appearance-matched source/display experiment or a measured observer prediction.

Models and coordinates

CIELAB uses the standard piecewise cube-root/linear transform with the selected reference white. L* is lightness, C*ab is chroma, and h is hue angle. Equal coordinate steps are not a guarantee of equal perceived differences.

CIECAM02 follows CIE 159:2004. CAM16 follows Li et al. (2017); it is not presented as an exact implementation of the later CIECAM16 specification in CIE 248:2022, which differs near black. Hellwig 2022 uses the modified correlates on the CAM16 basis. Hellwig / CAT02 composition combines those correlates with CAT02/HPE and is explicitly a composition, rather than the published CAM16-basis model.

J is lightness; Q brightness; C chroma; M colorfulness; s saturation; h hue angle. The atlas samples J, C, M and s from 0 to 100. Q runs from 0 to the current model's adopted-white brightness. These are exploration bounds, not universal model maxima or a complete color solid. Hue-axis samples run 0° to 350° without a duplicated 360° seam. A fixed hue can be set anywhere from 0° to 360°; 360° is equivalent to 0°.

Viewing conditions

Reference-white luminance factor Yw is fixed at 100. Yb is the background luminance factor on that same scale. In CAM modes the plot background is XYZ proportional to the adopted white at Yb/100. In CIELAB, background L* directly controls a neutral background.

Explicit La uses the entered adapting luminance in cd/m². Derived La uses La = Lw × Yb/100, where Lw is adopted-white luminance in cd/m². Only the operative luminance field is enabled. The app's input ranges are practical exploration limits, not mathematical or perceptual validity guarantees.

Automatic D computes adaptation from surround F and La. Manual D uses an explicit 0–1 override. Viewing changes recompute the atlas and brightness sampling.

D50 uses MATLAB's tabulated whitepoint. Small differences from rounded ICC PCS D50 constants are numerical conventions, not new measured whitepoints. D55 is also available as a distinct white.

Vision approximations

Protan, deutan and tritan modes use a Brettel-style two-wing projection in the HPE cone basis with the selected white as neutral. Protan/deutan anchors are 475/575 nm; tritan anchors are 485/660 nm. The published Brettel et al. (1997) construction used Stockman fundamentals and an equal-energy neutral. This app's HPE/selected-white variant is an exploratory approximation, not validated reproduction of a particular observer.

The projection acts on model XYZ before the selected-gamut and sRGB checks. Axes and requested appearance coordinates retain the values before projection. XYZ/RGB readouts and gamut classifications describe the projected colors. Each branch is linear; the complete two-wing transform is piecewise linear. Neutral preservation, anchor preservation and idempotence test the construction, not individual visual experience.
